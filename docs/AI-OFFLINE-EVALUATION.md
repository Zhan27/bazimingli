# 已有模型回复的离线评测

此工具读取本地保存的回复，重新计算对应出生输入并检查现有JSON契约、命盘标识、四柱和事实/规则ID引用。逐例结果与按模型、Prompt、规则、格式、请求维度分组的统计分开保存。借鉴 [MingLi-Bench固定版本](https://github.com/DestinyLinker/MingLi-Bench/blob/b7433280fd86d7a7c27debbc47d0303c218f0bfd/mingli_bench/benchmark.py) 的逐例记录与聚合组织，自行实现，未移植其数据或模型调用器。

## 运行

在仓库根目录使用Node22及以上。先生成一个可编辑的完整合成样例，再生成报告。

```powershell
node scripts/evaluate-ai-responses.cjs --example sample.json
node scripts/evaluate-ai-responses.cjs sample.json report.json
```

样例明确标记为 `synthetic`，包括一个完整回复与一个截断回复，不是模型实测结果。评测已取得的真实回复时，将 `inputKind` 改为 `recorded-model-responses`，替换每条输入、元数据与 `text`。命盘和回复在本地处理，运行评测不会发送模型请求。生成样例和报告时，目标文件都必须不存在。输入文件与报告路径必须不同，中文和空格路径可用引号包裹。

命令成功写出报告时退出码0，包含契约不通过的案例仍属于成功生成报告。文件读取、数据集结构或写入失败返回1。可在CI中读取 `summary.failed` 和 `summary.notEvaluated` 自行制定门禁。

## 输入字段

顶层为 `schemaVersion:"ai-offline-evaluation-v1"`、`inputKind` 和 `cases`。`inputKind` 必须是 `synthetic` 或 `recorded-model-responses`。最多200条案例，文件与序列化数据最多20MiB。

| 案例字段 | 含义 |
|---|---|
| `id` | 1—80位字母、数字、下划线或短横线，数据集内唯一 |
| `input` | 与 `calculateChart` 相同的出生输入及选项。请使用生成回复时的实际输入 |
| `model` | 操作者记录的请求模型名，最多120字符 |
| `promptVersion` | 生成回复时记录的Prompt版本，最多120字符 |
| `ruleVersion` | 生成回复时的计算规则版本，最多40字符。与当前评测引擎不符时单独标记并跳过 |
| `knowledgeVersion` | 建议提供生成时的知识目录版本，最多40字符。提供但不匹配时跳过；未提供保留 `null`，无法核对历史目录口径 |
| `text` | 已保存的原始回复字符串，最多100万字符 |
| `format` | 默认 `json`，也接受 `markdown`。Markdown仅标为未校验，不计入契约通过率 |
| `dimensionIds` | 请求过的1—18维ID数组，不能重复或为空。省略时要求全部18维 |
| `reportedLatencyMs` | 可选，操作者记录的耗时，0—86400000毫秒 |
| `reportedCost` | 可选，`{amount:0.002,currency:"USD"}`，非负且金额不超过1000000。货币代码为3位大写字母 |

无效日期、未知时辰、格式错误的元数据和过旧规则分别保留错误状态，一条无效案例不会吞掉其他案例。无效数据集版本、重复ID、总条数或总大小超限会拒绝整个数据集。

## 输出和分母

报告使用独立的 `schemaVersion:"ai-offline-evaluation-report-v1"`，再次当作输入会被拒绝，避免误把报告统计当成待评测回复。

`cases` 保存每条状态、命盘关联ID、请求元数据、错误类型和检查结果。报告不复制出生输入、原始回复及未知字段。元数据仍由操作者填写，模型名和Prompt版本没有独立验证。`chartId` 是关联标识，不是匿名化或认证标识。

每条最多保存100项错误详情，超出数量在 `errorDetailsTruncated` 中列明。`errorCounts` 与汇总始终统计全部已发现错误，不把详情截断当作错误减少。

`summary` 和每个 `groups[].summary` 都列出总条数、已检查、通过、未通过、未检查和错误分类。`contractPassRate` 的分母仅为已执行JSON契约检查的条数；零条已检查时为 `null`。规则不兼容、输入错误和Markdown计入 `notEvaluated`。请求相同维度但顺序不同的案例归为同组，不同维度集合分组。

每条案例表示一次已保存的回复，统计按回复计数。分组另外列出 `caseIds` 与成功计算出的 `chartIds`。不同组可能含有不同命盘或重复次数，通过率不能直接当作模型排名，比较时需先核对样本覆盖和请求条件。

报告的 `versions` 保留本次检查器的应用、计算规则、契约与知识目录版本。不同或缺失的声明知识版本单独分组。未提供历史知识版本时，引用检查使用当前目录，这不能证明回复生成时使用了相同资料。

延迟只对有效提供的记录求平均，并列明提供/缺失数量；完全缺失时均值为 `null`。费用按货币分别相加，缺失费用不会变成零。标签 `reported` 表明这些值来自操作记录，离线验证本身的运行时间不会冒充模型响应时间。`paidRequests:0` 只说明本次离线评测没有发出模型请求，不代表原回复免费。

这些数字反映结构与显式引用检查。自由文本是否正确、出处是否支持具体判断、真实模型质量和现实预测能力需要另行核验，本工具不输出这些准确率。

## 验证

本工具有12项回归，涵盖逐例故障、分组与命盘覆盖、维度子集、元数据与目录版本、缺失度量、币种分离、诊断详情上限、输入/报告版本隔离、中文路径、解析失败和覆盖保护。5.45本地最终172项Node、10项Python、97项Chrome共279项通过，静态检查0错误、32项既有警告、0新增警告。CLI另实际生成合成输入与报告，完整回复通过、截断回复拒绝，缺失费用/延迟未伪造为零。
