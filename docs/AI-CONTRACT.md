# AI contract and current scope

The pure contract in `src/ai/contracts.js` defines18 dimension inputs and required conclusion / fact IDs / rule IDs / explanation / uncertainty / alternative paths. It validates JSON structure, chart identity, pillar equality, referenced fact and source IDs, missing dimensions and explicit disallowed predictions. Error classes are `FACT_ERROR`, `RULE_INCONSISTENCY`, `REASONING_GAP`, `EXPRESSION_ERROR`. Direct API requests can target a dimension subset; the UI exposes per-card regeneration and missing-dimension retries.

`buildEvidencePrompt` creates separately versioned school prompts; `aiOutputSchema` provides a JSON Schema for compatible providers; Markdown parsing remains available. `src/knowledge/catalog.js` records original-project terms as **citation-pending**, with no invented original text or verified ancient edition. Implementation checks and traditional claims have different statuses. `evaluateAiResponse` evaluates only explicit contract/reference compliance; it does not prove correctness of free prose or predictive quality.

The shared request layer handles final SSE frames, chunk boundaries, UTF8 decoding, JSON-mode provider replies, bounded responses, idle/total timeouts and explicit cancellation. It never silently repeats a paid request and never displays raw server error bodies that could contain credentials. Tests use synthetic fixtures and mocked requests; no live paid-model comparisons were performed.

`src/ai/session.js` implements bounded attempt state: per-dimension acceptance, root/pillar mismatch rejection, immutable chart inputs, explicit Markdown-unverified status, cancellation/failure preservation, provider-origin-only metadata and revalidation of stored replies. A running stored attempt restores as interrupted; no request is automatically repeated.

## UI workflow (5.20)

Direct API generation defaults to JSON instructions. A separate selector opts into provider JSON Schema, or into explicitly unverified Markdown. An incompatible schema request fails visibly; switching formats and sending another paid request requires the user. Completed JSON is validated per dimension; a root identity mismatch rejects the attempt, while an invalid dimension leaves earlier accepted content in place. Free prose can still contradict its references: the label says **structure/reference checks**, not semantic or predictive verification. `high` means high uncertainty.

Each card shows the conclusion, computed facts, source IDs/statuses, explanation, uncertainty, alternative paths and generation metadata. Model names are the **requested** names, not independently verified provider versions. Prompt/rule/knowledge versions, provider origin and start/finish times are retained; API settings and authorization headers are excluded. No AI reply rewrites the computed chart or local score. Legacy heuristic wealth/education/scoring remains only as a collapsed, explicitly uncalibrated demonstration. Current prompt generation no longer requires numerical life scores, wealth amounts or education predictions.

The most recent chart's draft is held in tab-session storage, capped at1.8M serialized characters; response text is capped at1M characters. It includes birth data and replies, can survive browser session restoration, and has an independent clear control. If storage is denied, the UI warns that only page memory remains. Restoring a different chart recalculates locally without contacting a provider. Old-rule drafts can be inspected as raw text rather than silently applied. JSON fragments remain raw drafts until a complete object can be checked; complete earlier attempts/cards remain available after cancellation. Reloading does not resume a paid request automatically. Follow-up text is cancellable but is not added to the persisted18-card draft.

The optional legacy `/v1/divine` server-template route still accepts full Markdown only. The UI blocks JSON and subset requests on that route rather than silently sending a larger request. Re-extract templates and redeploy to update legacy prompt instructions; source uploads do not change an existing Worker. JSON/direct and per-card workflows can use an OpenAI-compatible chat proxy with server-template mode disabled.

Tests use synthetic charts, intentionally malformed replies, mocked HTTP/SSE streams and explicit cancellation. Real paid model comparisons, cross-provider JSON Schema compatibility trials and a complete classic-quotation audit remain unfinished.

`node scripts/check-ai-fixtures.cjs` reruns the fixed `synthetic-contract-v1` fixtures and emits `verification/ai-contract-evaluation.json`, also produced by `npm test` and uploaded by verification CI. Positive cases are generated protocol examples, negative cases are declared fault injections. Counts report contract expectations and injected faults rejected; they are not model accuracy, cost, latency or experimental prediction results. Invalid/truncated JSON correctly reports incomplete coverage.
